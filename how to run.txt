Run it properly (6 terminals)
0. Prerequisites: Docker Desktop, Node 18+, backend/venv active.
1. Infrastructure:
cd backend
docker compose up -d postgres redis
docker exec -it luxe-redis redis-cli ping  # already covered by compose redis
2. Backend setup (first time only):
.\venv\Scripts\Activate.ps1
$env:DB_ENGINE='postgres'  # or omit — postgres is default
$env:POSTGRES_PASSWORD='change-me'  # must match compose
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py createsuperuser  # phone-based now: enter 0912... as username
.\venv\Scripts\python.exe manage.py init_notification_templates
3. Run (4 terminals):
# T1 API
.\venv\Scripts\python.exe manage.py runserver 8000

# T2 Celery worker (Windows needs solo)
.\venv\Scripts\celery.exe -A config worker -l info -P solo -Q default,sms,inventory,media

# T3 Celery beat
.\venv\Scripts\celery.exe -A config beat -l info --scheduler django_celery_beat.schedulers:DatabaseScheduler

# T4 Frontend (repo root/frontend)
npm run dev  # -> http://localhost:3000
4. Smoke test:
- POST /api/auth/otp/request {"phone_number":"0912..."} → (mock SMS in console, no key set) → read code from auth_otp_code table → POST /api/auth/otp/verify → JWT
- Admin login with superuser phone + password → POST /api/admin/products/discount-section/activate/
- GET /api/products/?has_discount=true, GET /sitemap.xml, GET /robots.txt
Notes for your stage:
- Without SMS_IR_API_KEY, SMS is mocked to console — set the prod key in env only when testing real delivery (each test costs credit)
- DEBUG=True + SQLite fallback (DB_ENGINE=sqlite) still available for quick offline work, but run postgres for anything resembling real testing
- Remaining before deploy: payment gateway, SECRET_KEY/DEBUG=False/hosts (you said you'd handle those at deploy time)
Stop order: Ctrl+C beat → worker → runserver → docker compose stop.
